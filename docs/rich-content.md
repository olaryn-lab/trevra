# Rich content support matrix (TRV-040)

Which kinds of rich content (image, GIF, video, voice, document) each channel
Trevra writes through can carry, and why. The table and the reasons below are
generated from `src/shared/rich-content.ts`, the same module the server
enforces and the composer renders; `src/shared/rich-content.test.ts` fails when
this page drifts from it.

- `supported`: the file is attached and sent as an attachment.
- `link_only`: the channel has no attachment surface Trevra drives. An
  attachment is refused; put a link to the file in the text.
- `unsupported`: the channel cannot carry this content in any form Trevra
  controls.

## Why each cell is what it is

## Refusals

A refusal is never a silent drop. Every one carries a machine code and the
sentence that explains it:

| Code                       | Meaning                                                                                                          | HTTP                             |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| `content_type_unsupported` | The content type is `link_only` or `unsupported` on the channel, or its MIME type is outside the channel's list. | 422 (415 for post media uploads) |
| `attachment_too_large`     | One attachment is over the channel's per-file ceiling.                                                           | 413                              |
| `too_many_attachments`     | More attachments than the channel takes.                                                                         | 422 (400 for post media)         |

API error bodies are `{ error, code, reason, channel, contentType, index }`.

## Where it is enforced

Write paths (refused before anything is stored):

- Workflow save and validate (`saveWorkflow`, `POST /api/linkedin/manager/workflows/validate`).
- Campaign create, campaign sequence edit, and applying the latest workflow to
  pending members (`managed-campaigns.ts`).
- Inbox reply (`enqueueReply`) and queued-message edits (`POST /api/linkedin/actions/:id/body`,
  which also accepts `attachments: []` to strip an attachment from a queued row).
- LinkedIn post media upload (`normalizePostImageInput`, the raw-body size
  limit, and the per-post count).
- Buffer draft creation from a post that has media.
- Campaign email steps (`executeEmail`) and the prepared-action adapters for
  `email.send`, `community.reply` and `buffer.create-draft`.

Send boundary (checked again where the content leaves Trevra):

- The runner holds a member on a step whose chosen variant breaks the matrix
  (`blocked:<stepId>` with the reason) instead of planning the action.
- The workspace approval gate holds a planned action whose stored attachment
  breaks the matrix; it cannot be approved until the attachment is removed or
  replaced. Attachments stay inside the exact approval payload hash, so
  changing one invalidates an existing approval.
- The local worker releases such an action back to `planned` with
  `failure_kind = 'content_unsupported'` before opening a browser, so a legacy
  row is held and re-checked, never sent and never dropped.
- The DM and InMail driver re-checks the downloaded bytes (real MIME type and
  size) against the row before uploading; a mismatch leaves the text unsent.

Voice is unsupported everywhere: LinkedIn voice messages can only be recorded
in the LinkedIn mobile app. Video has no verified upload path in LinkedIn
messages or posts.
